======================================================================
 2. Replication lag during a bulk load
======================================================================
The AquaFlow schema and the Portfolio 2 seed data (about 400 MB) are
loaded on the primary only. Every 3 seconds, the primary reports how far
the replica's replay is behind its current WAL position.

Schema created on the primary. Starting seed.sql ...
time       replica_behind     replay_lag       replica_rows_visible
10:42:19   0 bytes            00:00:00.006     300000
10:44:02   0 bytes            00:00:00         300000

Seed finished and the replica has caught up. Row counts on each server:
[primary]> SELECT (SELECT count(*) FROM delivery_request) AS requests, (SELECT count(*) FROM trip_status_history) AS status_history;
 requests | status_history 
----------+----------------
   300000 |        1155345
(1 row)

[replica]> SELECT (SELECT count(*) FROM delivery_request) AS requests, (SELECT count(*) FROM trip_status_history) AS status_history;
 requests | status_history 
----------+----------------
   300000 |        1155345
(1 row)

 3. The replica is read-only
======================================================================
A hot standby accepts queries but refuses every write. All writes must go
to the primary.

ERROR:  cannot execute INSERT in a read-only transaction
