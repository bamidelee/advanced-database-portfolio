
======================================================================
 1. Load live tanker state from PostgreSQL
======================================================================
PostgreSQL remains the system of record. Redis holds the fast-changing
live state: positions, availability and heartbeats.

> ZCARD geo:tankers
938

> ZCARD geo:tankers:available
338

> DBSIZE
2176

> MEMORY USAGE geo:tankers
90035

Customer address 2 is at latitude 6.433002, longitude 3.419713

======================================================================
 2. The data model
======================================================================
Each tanker is a hash. Positions are in a geo set, which Redis stores as
a sorted set scored by a 52-bit geohash, so nearby points have nearby
scores and a radius search is a range scan.

======================================================================
 5. First accept wins
======================================================================
Two vendors accept request 9001 at the same moment. SET ... NX only
succeeds if the key does not exist yet, and Redis executes commands one
at a time, so exactly one claim succeeds. EX 30 releases the claim
automatically if the vendor's app never confirms.

> SET request:9001:accepted tanker:806 NX EX 30
OK

> SET request:9001:accepted tanker:902 NX EX 30
(nil)

> GET request:9001:accepted
tanker:806

> TTL request:9001:accepted
30

======================================================================
 7. Live location updates while driving to the customer
======================================================================
Each GPS ping updates the position, the hash and the heartbeat in one
MULTI/EXEC transaction. GEOADD on an existing member moves it.

Distance before driving: 0.3289 km
> MULTI / GEOADD geo:tankers 3.421435 6.431904 806 / HSET tanker:806 lat 6.431904 lng 3.421435 / SET tanker:806:alive 1 EX 60 / EXEC
  Ping 1: 0.2260 km from the customer
> MULTI / GEOADD geo:tankers 3.420652 6.432403 806 / HSET tanker:806 lat 6.432403 lng 3.420652 / SET tanker:806:alive 1 EX 60 / EXEC
  Ping 2: 0.1232 km from the customer
> MULTI / GEOADD geo:tankers 3.419870 6.432902 806 / HSET tanker:806 lat 6.432902 lng 3.419870 / SET tanker:806:alive 1 EX 60 / EXEC

======================================================================
 8. Heartbeat expiry
======================================================================
Tanker 902's app stops reporting. Its heartbeat key was given a 2 second
lifetime; once it expires, matching skips the tanker even though it is
still in the available set. No cleanup job is needed for correctness.

> SET tanker:902:alive 1 EX 2
OK

> TTL tanker:902:alive
2

(waiting 3 seconds)
> EXISTS tanker:902:alive
0
